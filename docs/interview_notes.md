# 面试讲解稿与常见问题

## 1. 项目一句话介绍

我做了一个面向电商售后场景的企业客服多 Agent 系统，支持订单查询、退款政策问答、售后工单创建和人工转接。系统把用户问题先做意图识别，再根据意图调用订单 API、政策知识库或工单 API，最后生成客服回复。

## 2. 为什么要用 Agent

普通聊天机器人只能生成文字，但企业客服需要连接业务系统。比如订单状态必须查订单 API，退款政策必须基于知识库，投诉必须创建工单。所以我把系统设计成 Agent，让它根据用户问题选择合适工具完成任务。

## 3. 为什么要用 RAG

退款、物流、售后政策经常变化，不能让模型凭记忆回答。RAG 可以先从企业知识库检索相关政策，再让模型基于检索结果回复，从而减少幻觉并方便溯源。

## 4. 工具调用失败怎么办

我的设计里工具返回统一结构：

```json
{"ok": true, "data": {}}
{"ok": false, "error": "错误信息"}
```

Agent 会根据 `ok` 字段判断是否继续执行、追问用户或转人工。

## 5. 如何避免 Agent 乱答

- 订单状态必须来自订单 API
- 政策回答必须来自知识库检索结果
- 信息不足时先追问
- 投诉、赔偿、隐私、支付异常等高风险问题转人工
- 保存工具调用和处理步骤，方便审计

## 6. 后续如何优化

- 用 LangGraph 重构工作流
- 增加 Chroma/FAISS 向量数据库
- 增加 rerank 提升检索质量
- 增加评估集测试意图识别准确率和工具选择准确率
- 增加日志、缓存、限流和人工审核
- 用真实 LLM 替换规则分类和回复模板
